# ADR 0001：规则引擎结构——参数化 JSON + 固定计算结构

- 状态：已采纳
- 日期：2026-10-12
- 关联：CLAUDE.md §4、§6、§8 M0

## 背景

CLAUDE.md 要求规则“可配置、可版本化、结果可追溯”，引擎是“纯 Python 包，规则写在 JSON 配置中，用 Decimal 计算，不做任何 IO”，并且规则 v1 必须逐位复现 legacy。

## 选项

1. **通用表达式 DSL**：在 JSON 里写公式（如 `"min(x * 0.5, 5)"`），引擎解释执行。灵活，但要自己写解析器和沙箱，测试面大；M0 只有一套规则，用不上这种灵活性。
2. **参数化 JSON + 固定计算结构**：计算结构（总分 = 素质 ÷ d × w₁ + GPA × w₂；素质 = 思想品德 + 综合能力；……）写在代码里，所有数值（权重、满分、封顶、阈值、去极值比例、小数位数）以及规则 id、出处写在 JSON 里。基础分只提供两种规则类型：`linear_capped`（min(rate·x, cap)）和 `threshold`（x ≥ t 记 p 分）。
3. **规则全部写在代码里**：最简单，但规则不可配置，也不能版本化。

## 决定

选 2。

- 规则文件 `rules/<id>.json`，结构由 `rules/schema.json`（JSON Schema 2020-12）约束；数值一律为十进制字符串，避免 JSON 浮点。
- 引擎 `zongce_engine` 不读文件：调用方读 JSON，交给 `RuleSet.from_dict()`；引擎只做计算所需的校验，完整结构校验由测试和 CI 用 JSON Schema 完成。
- 每条规则有唯一 `id` 和非空 `source`；计算结果 `ScoreResult.items` 记录每条规则的原始值、得分、是否触发上限 / 下限，以及评议人数和每端去掉的人数。
- 舍入语义只提供 `js_math_round`（`floor(x + 0.5)`，即 JS `Math.round`），对非负数就是四舍五入；不用 Python 的 `round()`（银行家舍入）。
- 字符串解析（评议名单文本框、表格导入取数）作为纯函数放在 `zongce_engine.parsing`，逐字符复现 JS 的 `\s`、`parseFloat` 和取数正则。

## 后果

- 细则 v2 需要新增计算结构（如思想品德附减分、能力分逐项加分，见 `docs/rules-issues.md`）时，要在引擎里加新的规则类型，并相应扩展 schema，而不只是改 JSON。这是有意的：结构变化要经过代码审查和测试。
- 源码约束由测试强制执行：`engine/tests/test_purity.py` 检查引擎源码中没有浮点字面量、没有 `float`、没有文件、网络或系统相关的导入。
