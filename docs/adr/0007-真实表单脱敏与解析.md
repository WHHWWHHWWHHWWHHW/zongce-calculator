# ADR 0007：真实表单的脱敏与解析

- 状态：已采纳（负责人 2026-10-20 授权：移动原始数据、脱敏并读取脱敏结果、引入 pdfplumber 并使用 LibreOffice）
- 日期：2026-10-20
- 关联：CLAUDE.md §3 第 2 条、§8 M4、§11、§13 第 2 项；ADR 0006；`docs/reports/real-forms-20261020.md`

## 背景

负责人提供了 2025–2026 学年学院各部门的综测汇总，共 25 个文件：Excel、带文字层的 PDF、doc/wps/docx。这批数据未脱敏，包含全院学生的姓名和学号。M4 需要用真实表单检验解析与匹配，但真实数据不能进仓库、不能进对话（§11）。

## 决定

1. **原始数据放在负责人电脑的 `real_data/<学年>/原始/`**（已在 `.gitignore`），只在本机处理，不上传云端。
2. **先脱敏再学习**：`ai/eval/desensitize.py` 在本机运行。
   - 同一姓名在所有文件中换成同一个代号（学生0001、教师001），8 位以上的数字按位数换成随机数字。
   - 对照表和密钥写在 `real_data/<学年>/私密/`。输出与对照表只能写到 `real_data/` 或 `data/` 下。
3. **姓名收集分三层**：
   - 表头明确的人名列（姓名、获奖学生、项目成员、指导教师等；PDF 后续页沿用表头）。
   - 文字中的“班级 + 姓名”、整行姓名和“负责人：”之类的标注。
   - 与已替换代号并列的词，多轮补充。
   按写法推断的词要过滤掉专业简称、职务词和含“奖、级、部、赛”等字的词。
4. **泄漏检查必须为 0 才能使用脱敏数据**：
   - 用对照表逐字扫描输出。
   - 人名列中不得有非代号汉字。
   - 可疑项（像“班级 + 姓名”或整行姓名但未替换）逐条按形状核查，不显示原文。
5. **新依赖 pdfplumber**（`zongce-ai` 的运行时依赖）：用来提取 PDF 表格与文字。
   - 替代方案一：系统自带的 `pdftotext` 只能给出排版文字，取不到表格结构。
   - 替代方案二：PaddleOCR 太重，而且这些 PDF 有文字层，不需要 OCR。
   - doc/wps/docx 用本机已安装的 LibreOffice 转成 PDF，不引入 Python 依赖。
6. **活动获奖名单的解析**（`zongce_ai.activity_lists`）：
   - 识别“活动名称 → 等级与分值 → 名单”结构，再按名单写明的分值和等级对应申报目录选项。
   - 分值相同时用等级名称、等级文字和活动级别区分；学院各部门的活动默认为院级。
   - 仍不唯一就不选，交给人工。

## 后果

- **结论**（见 `docs/reports/real-forms-20261020.md`）：真实名单大多没有学号，需要按“班级 + 姓名”匹配学生，并维护专业别名（“人工智能”与“智能”）。
- **待负责人确认**：到梦空间的哪一列是第二课堂积分，志愿章的哪一项是公益劳动次数。确认前不导入。
- **尚未接入平台**：名单比对接口目前仍按学号匹配；按班级 + 姓名匹配、上传 PDF 名单需要后续实现，并用账号表作名册。
- **残余风险**：只出现在叙述文字里、又不在任何名册和名单中的姓名，可能识别不全。因此脱敏数据也只留在本机，不提交。
