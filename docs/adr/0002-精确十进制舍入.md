# ADR 0002：精确十进制舍入，不模拟 legacy 的二进制浮点误差

- 状态：已采纳（项目负责人 2026-10-12 决定）
- 日期：2026-10-12
- 关联：CLAUDE.md §3 红线 7、§4.3、§5.1、§8 M0；`docs/rules-issues.md` R-008

## 背景

M0 要求引擎与 legacy 对拍“0 差异”。随机对拍发现：精确十进制值恰好落在 .5 舍入边界（第 5 位小数是 5、后面全为 0）时，legacy 的 IEEE 754 双精度运算得到略小的近似值并被舍掉，比四舍五入少 0.0001。

- 20000 组随机输入（种子 7）中有 189 组出现这种差异，其中综测成绩 38 组（0.19%），其余只涉及页面上显示的中间分数。
- 用双精度逐步模拟 legacy（`tests/support/legacy_float.py`）能逐字复现 jsdom 中 legacy 的全部输出，差异全部来自上述原因，方向都是 legacy 少 0.0001。
- 《实施办法》正文第六条规定“根据四舍五入规则……精确到小数点后 4 位”。按精确值计算，这些边界值应该进位。

## 选项

1. **引擎按精确十进制四舍五入**，把这类差异记为 legacy 的已知问题；对拍只放行这一类差异。
2. **引擎模拟 legacy 的二进制浮点**，做到真正逐位一致：违背“引擎中禁止 float”（CLAUDE.md §10）的初衷，并把 legacy 的误差固化进平台。
3. **引擎按精确值计算，同时修 legacy**：两边 0 差异，但会改变 legacy 的计算结果，外部网站“济南大学校园通”上的版本也不会同步更新。

## 决定

选 1（项目负责人决定）。

## 后果

- 对拍判定（`tests/parity/test_parity.py`）：一个差异只有同时满足以下条件才视为已知差异——精确值恰在 .5 边界；引擎比 legacy 多 0.0001；双精度模拟器逐字复现了 legacy 的输出。双精度模拟器还必须对全部用例与 jsdom 一致。其余任何差异都会使测试失败。已知差异的数量以 `ParityKnownDifference` 警告输出，并写入报告文件。
- 植入错误的验证：把引擎的 `js_round` 换成银行家舍入后，2000 组里有 228 组被判为无法解释的差异，测试失败。
- 约 0.2% 的学生，平台的综测成绩会比 legacy 计算器高 0.0001。今后 M3 回溯测试与官方结果比对时，要留意官方系统采用的是哪种舍入。
- legacy 文件不改。
