# ADR 0006：AI 辅助审核的基础部分

- 状态：已采纳（负责人 2026-10-20 同意“M3 等数据时先做 M4 基础”）
- 日期：2026-10-20
- 关联：CLAUDE.md §1 目标 5、§3 第 4、8 条、§6 AI 模块、§8 M4、§11

## 背景

M4 要求学院上传官方表单后，系统识别并与学生申报匹配，一致的进入“可快速通过”，其余转人工。OCR 和大模型需要负责人确定模型与密钥（§13 第 4 项），真实样本也还没有（§13 第 2 项）。在此之前，可以先把不依赖它们的部分做好。

## 决定

1. **流水线独立成包** `ai/pipeline`（`zongce_ai`，uv 工作区成员）。它是纯函数：输入字符串二维表和申报列表，输出建议；不访问数据库，不改分。后端负责读文件、查库，并把确认结果写成正式审核。
2. **先做获奖名单比对**。学生申报能力分时选了项目和等级，学院的获奖名单可以逐条核对。基础分（第二课堂、体测等）已经由管理员直接导入学院成绩表，不需要比对。
3. **等级识别用规则，不猜**。把“省一”“金奖”“第五名”等写法拆成类别、级别、奖项、名次几个维度，与申报目录选项逐一对应。多个选项都符合、或者缺少区分信息（比如没写赛事类别）时，不给选项，转人工处理。整表共同的信息（如“一类赛事”）由上传者填写。
4. **分流**：学号、姓名、项目、等级都与一条待审核申报一致，并且置信度不低于阈值（默认 0.9，可配置），才建议“可快速通过”。其他情况一律人工复核或仅作提示。
5. **确认必须由人完成**。“可快速通过”只是列表。审核员勾选后批量确认，每条都按正常的“通过”审核处理，审核理由写明名单来源，审核记录和审计日志照常写入。
6. **`AI_PROVIDER`**（环境变量 `ZONGCE_AI_PROVIDER`）默认 `none`：只支持表格，上传图片或 PDF 返回明确的错误，平台其余功能不受影响。`local` 和 `remote` 的接口已经留好（`providers.py`），尚未接入。`remote` 外发前，学号用带密钥的哈希代替，姓名换成占位符；日志只记录摘要（`privacy.py`）。
7. **评测**：`ai/eval/evaluate.py` 输出学号准确率、等级准确率、快速通过的精确率和召回率。合成评测集由 `scripts/gen_fake_data.py --ai-eval` 生成并入库，保证结果可以复现。

## 依赖

没有新增第三方依赖：流水线只用 Pydantic（后端已有）。PaddleOCR 和大模型 SDK 等接入时再评估，并另写 ADR。

## 后果

- 合成评测集上的指标接近 100%，因为合成数据的写法与匹配规则同源。这个结果不能作为“准确率 ≥ 95%”的依据（见 `ai/eval/README.md`）。
- 规则匹配覆盖不到的写法会落到人工复核，不会误放行。以后接入大模型抽取时，输出同样要经过 Pydantic 校验和这套分流，才能进入“可快速通过”。
- 前端页面（上传名单、查看建议、批量确认）还没有做。
