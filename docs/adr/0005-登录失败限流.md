# ADR 0005：登录失败限流

- 状态：已采纳（M1 加固，负责人 2026-10-20 同意按计划推进）
- 日期：2026-10-20
- 关联：CLAUDE.md §8 M1（登录与权限）、§11（安全）

## 背景

学生账号的初始密码是随机生成后线下发放的，学号公开可见。如果不限制登录失败次数，可以对某个学号无限次尝试密码。

## 决定

1. **按账号和按 IP 分别计数**。在滑动时间窗内（默认 15 分钟），同一账号失败 5 次，或同一 IP 失败 20 次，就拒绝登录，返回 `429 too_many_requests`；响应头 `Retry-After` 给出等待秒数。锁定期间即使密码正确也拒绝，否则锁定就失去了意义。三个数值都可以在 `.env` 里配置。
2. **登录成功后清零该账号的计数**；IP 的计数不清零，防止攻击者夹带自己的账号来重置计数。
3. **计数放在进程内存**（`zongce_backend/ratelimit.py`），不引入 Redis 等新依赖。负责人决定先在本机运行，单进程足够。记录数超过上限时清理过期记录，避免内存无限增长。
4. **按真实客户端 IP 计数**。uvicorn 默认只信任 127.0.0.1 发来的 `X-Forwarded-For`。前端开发服务器的代理开启了 `xfwd`；以后放到 nginx 等反向代理后面时，要用 `FORWARDED_ALLOW_IPS` 指定代理地址，否则所有人会被算成同一个 IP。这一点已写进 `deploy/.env.example`。

## 后果

- 有人可以故意输错某个学号的密码，让这个账号被锁 15 分钟。锁定是暂时的，而且这样做比不限流的风险小。如果真的发生，管理员可以等待锁定结束，或者重启服务来清零计数。
- 重启服务会清零计数；改成多进程或多机部署时，需要把计数换成共享存储（新 ADR）。
- 没有引入验证码，后续如有需要再评估。
