# ADR 0008：本机一键演示，以及到梦空间、志愿章汇总的导入

- 状态：已采纳（负责人 2026-10-21 23:48 要求“在本机验证各项功能，从本机登录本机的后端”；2026-10-21 确定两张表的列口径）
- 日期：2026-10-22
- 关联：CLAUDE.md §3、§11、§13 第 3、8 项；ADR 0003、0004；`docs/reports/local-verify-20261022.md`、`docs/reports/college-sources-20261022.md`

## 背景

1. 负责人决定先在本机运行（§13 第 3 项），并要求在自己的电脑上验证功能。
   - 原来的做法要开两个进程：后端 `zongce serve`，前端 `pnpm dev`。
   - 负责人的 Mac 上没有装 Node.js。仓库里已有的 `frontend/node_modules` 和 `.venv` 是在联动的 Linux 环境中安装的，Mac 上不能直接用。
2. 到梦空间学分汇总和志愿章汇总是学院各部门实际导出的表，列名与平台成绩表不同。
   - 志愿章汇总没有学号，按年级分成多个工作表。

## 决定

1. **后端可选提供前端构建产物**：配置 `ZONGCE_FRONTEND_DIST`。
   - `/assets` 返回静态文件；`/api` 以外的路径返回 `index.html`（前端路由为 history 模式）；`/api` 下的未知路径仍返回 JSON 404。
   - 解析路径后检查不越出构建目录。
   - 不引入新依赖，只用 FastAPI 自带的 `StaticFiles` 和 `FileResponse`。正式部署仍建议由 nginx 提供静态文件。
2. **`scripts/local-demo.sh`**：
   - 用合成演示库（`seed-demo`）启动，只监听 127.0.0.1。
   - 演示库、JWT 密钥和演示密码都放在 `data/local-demo/`，已被 git 忽略，文件权限为 600。
   - Python 环境按系统和架构分开存放（如 `.venv-darwin-arm64`），不覆盖其他环境的 `.venv`。
   - 前端产物可以在任意一台装了 Node 的环境中构建，`dist/` 与系统无关。
3. **学院成绩导入扩展**：
   - 关键词“积分总和”对应第二课堂，“总章数”对应公益劳动。
   - Excel 的每个工作表分别识别表头。
   - 没有学号列时，按“班级 + 姓名”找学生，班级写法先统一。
   - 找不到或同班同名的行逐行报错，**不按姓名猜测**。成绩表直接影响分数，写错的代价比人工补录高。

## 后果

- 负责人在 Mac 终端运行一条命令，就能用浏览器访问完整平台。19 项功能已在本机验证通过。
- 志愿章约 6% 的行因班级对不上需要人工处理（用脱敏数据模拟）。如果学院在表中加上学号列，可以完全避免。
- 运行中的服务不会自动加载新代码。更新代码后需要在终端按 Ctrl+C，再重新运行脚本。前端产物重新构建后无需重启，刷新页面即可。
