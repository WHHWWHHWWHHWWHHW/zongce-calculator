# 回溯测试说明（M3）

用一个班的历史综测数据重新核算，与学院当年公布的结果逐项比对，检验平台算得对不对（CLAUDE.md §8 M3）。第一次用真实数据运行的结果见 `docs/reports/backtest-20261021.md`。

## 1. 准备数据（在本机完成，不要提交、不要发到对话里）

一个 Excel（.xlsx）或 CSV 文件，第一行是表头，每行一名学生。放在仓库的 `data/` 或 `real_data/<学年>/原始/` 目录下，例如 `data/history/2024-2025.xlsx`；这两个目录都已被 git 忽略。

| 列 | 表头写法（包含其中一个词即可） | 内容 |
|---|---|---|
| 学号 | 学号 | 必填。可以换成脱敏编号（如 S01），只要每行不同 |
| 学业水平 | 学分绩点、绩点、GPA、学业水平 | 平均学分绩点 |
| 第二课堂 | 第二课堂 | 积分 |
| 公益劳动 | 公益劳动、公益 | 次数 |
| 体测 | 体质健康、体测 | 成绩 |
| 宿舍 | 宿舍 | 学年平均成绩 |
| 能力分 | 能力分 | 当年审核通过的能力分合计 |
| 思想品德四项 | 政治素养、品德修养、纪律观念、诚信评价 | 一个分数，或全班评议名单（多个数字，用逗号或空格分隔） |
| 综合素质（可选） | 综合素质评价总分、综合素质评价成绩 | 当年直接给出综合素质总分时填写，此时不用填上面各项。写“放弃”的按 0 分核算，报告中单独计数（R-010） |
| **官方结果** | 以“官方”“公布”或“公示”开头：官方综测成绩、官方综合素质、官方思想品德、官方综合能力 | 学院公布的结果，至少要有一列 |

- 不需要姓名列；有其他列（如备注）会被忽略，并在报告中列出。
- 官方结果列不以“官方”开头时（如学院导出模板的“班级测评总分”），用 `--official 列名=字段` 指定，字段为 `final_score`、`quality_total`、`moral_total` 或 `competence_total`，可以写多次。
- 官方结果保留几位小数，就按几位比较（最多 4 位）。如果 Excel 单元格里存的是未舍入的长小数，会先四舍五入到 4 位再比较。

## 2. 运行

```bash
uv run zongce backtest data/history/2024-2025.xlsx --label "2024—2025 学年某班（脱敏）"

# 学院导出模板（综合素质直接给出，总分列叫“班级测评总分”），结果都写到 real_data/
uv run zongce backtest real_data/2025-2026/原始/班级综测/<文件>.xlsx \
  --official 班级测评总分=final_score \
  --report real_data/2025-2026/回溯/backtest-report.md \
  --details real_data/2025-2026/回溯/明细.csv
```

生成两个文件：

| 文件 | 内容 | 能否提交 |
|---|---|---|
| `docs/reports/backtest-日期.md` | 统计报告：比对人数、各口径一致率、差异分类计数。不含学号、姓名、分数 | 可以（M3 交付物） |
| `data/backtest/details-日期.csv` | 逐条差异：学号、官方值、各口径算出的值、分类，以及空白的“人工核查说明”列 | **不能**，只留在本机 |

明细文件只能写到仓库的 `data/`、`real_data/` 目录或仓库以外，写到其他位置会被拒绝。用真实数据时，报告也先写到 `real_data/`，核对无个人信息后再整理进 `docs/reports/`。

## 3. 三种口径和差异分类

- **规则 v1**：平台现行口径，逐位复现 legacy，只对最终结果四舍五入。
- **中间值也舍入到 4 位**：《实施办法》第六条“各项成绩精确到小数点后 4 位数”的另一种读法（`docs/rules-issues.md` R-005）。
- **最终结果截断到 4 位**：多余的小数位直接截去，不四舍五入。2025–2026 学年学院导出表就是这样算的（R-011）。

规则 v1 与官方结果不一致的地方，按下面的顺序归类：

1. **可由 R-005 解释**：换成“中间值也舍入”口径后与官方一致。
2. **可由截断解释（R-011）**：最终结果改为截断后与官方一致。精确值恰在 .5 边界、官方少进一位的情况也归在这里。
3. **舍入边界（R-008）**：精确值恰好落在 .5 舍入边界，官方结果少进了一位，且不属于上一类（例如综合素质等小计）。legacy 计算器和 Excel 都用二进制浮点，会出现这种情况（ADR 0002）。
4. **无法解释**：以上都不是，需要逐条核查，例如当年的输入数据与表中不同、人工计算有误、规则有未记录的特殊处理。查明后把原因写进明细文件的“人工核查说明”列，并把**归纳后的**原因（不含个人信息）补充到报告里。

CLAUDE.md §8 要求“每一处差异都必须有解释”：报告中“无法解释”一列必须在核查后清零或逐类说明，才能作为 M3 的结果。

## 4. 结论怎么用

- 如果大部分差异属于 R-005，说明学院实际按“中间值也舍入”计算，应由负责人决定是否在新规则版本中采用（引擎已支持，规则字段 `final.intermediate_decimal_places`）。
- 如果大部分差异可由截断解释，说明学院实际按截断计算，与办法原文“四舍五入”不一致，同样由负责人决定新规则版本采用哪一种（引擎已支持，规则字段 `final.rounding: "truncate"`）。
- 改动计分规则后要提醒“济南大学校园通”的维护者同步（CLAUDE.md §2.2）。
