## P-001 §7 目录结构补充 M0/M1 新增的路径

- **原文**：§7 目录树中没有以下路径。
- **建议增加**：
  - `rules/ability-catalog-*.json`：能力分申报目录，随规则版本一起导入；
  - `backend/migrations/`：Alembic 迁移；
  - `docs/api/openapi.json`：接口文档，前端类型的唯一来源；
  - `docs/本机运行.md`、`scripts/check.sh`（本地一键检查，与 CI 相同）；
  - `docs/claude-md-proposals.md`（本文件）。
- **理由**：§7 是目标结构，新加入的人和 AI 会以它为准。

## P-002 §10 TypeScript：明确前端类型来源

- **原文**：“API 类型从 OpenAPI 生成，或者集中手写在一处”。
- **建议改为**：“API 类型一律从 `docs/api/openapi.json` 生成；后端改了接口必须运行 `uv run zongce export-openapi docs/api/openapi.json`，测试会检查两者一致。”
- **理由**：后端测试已经强制这个文件与代码一致，前端直接用它即可，不再需要手写。

## P-003 §9.2 上一个里程碑的 PR 未合并时的分支策略

- **建议增加**：“上一个里程碑的 PR 尚未合并时，新里程碑分支基于上一分支创建（堆叠 PR），PR 的 base 指向上一分支；上一个合并后再改到 main。”
- **理由**：M1 就是在 M0 未合并时这样做的，写进规范可以避免以后有歧义。

## P-004 §9.3 / §12 检查命令统一为 `scripts/check.sh`

- **建议增加**：会话结束时运行 `bash scripts/check.sh`（ruff、mypy --strict、引擎覆盖率 100% + 对拍、后端覆盖率 ≥ 80%），汇报中引用它的输出。
- **理由**：本地和 CI 共用同一份命令，汇报的数字更容易复现。
