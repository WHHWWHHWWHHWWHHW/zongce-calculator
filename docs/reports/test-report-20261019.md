## 2. 计分正确性

- **黄金用例**：G1 3.7252、G2 4.6563、G3 4.1000，引擎与 legacy 页面（jsdom 中运行原页面）一致。
- **随机对拍**：默认 2000 组（种子 20261012），无法解释的差异 0；已知浮点边界差异 20 组，其中综测成绩 2 组。2026-10-12 另跑 20000 组（种子 7）：无法解释的差异 0，已知差异 189 组，其中综测成绩 38 组（0.19%）。已知差异的成因与处理见 ADR 0002。
- **对拍有效性**：故意把舍入改成银行家舍入后，2000 组里有 228 组被判为无法解释的差异，测试失败。
- **端到端复现**：G1 数据加上审核通过的 5 分能力分，经“导入 → 申报 → 审核 → 核算”后，学生页面显示 3.3127，与手算 3.3127375 舍入后一致。

## 3. 端到端用例

| 用例 | 覆盖 |
|---|---|
| 管理员准备数据（API） | 新建学年、开放申报、导入账号（CSV）、导入学院成绩表 |
| 学生申报 | 首次登录强制改密 → 新建申报（建议分 5.0000）→ 上传 PDF 证明 → 提交 |
| 审核员通过 | 申报分与建议分不一致的行标红并提示原因 → 填写理由后通过 |
| 管理员核算与导出 | 核算 2 人 → 排名显示 3.3127 → 导出 Excel（文件名、xlsx 格式） |
| 375px 宽度 | 登录、首页、预估、公示、审核、管理后台、改密页无整页横向滚动；预估可用 |
